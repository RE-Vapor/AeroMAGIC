## 接线结论

`macarons/testers/magician_planning.py` 与 `macarons/testers/scene.py` 现在共用同一组规划深度 helper。`false + DA3` 在加载规划模型和数据前完成以下检查：

1. `kind_depth_map` 必须严格解析为已注册的 `DA3`；没有 GT fallback。
2. 每个请求场景必须在 `da3_scene_units_per_meter` 中有显式正值标定；`scene_scale_factor=10` 不再被误当物理单位。
3. provider 输出的 `valid_mask & error_mask` 同时用于 point cloud 和 signed distance；同一 provider 相机用于 point cloud、FoV proxy 和 signed-distance 投影。
4. point cloud、proxy view/occupancy/out-of-field 状态和 GT-reference coverage 通过共享 helper 更新，两个入口不再各自复制这段逻辑。

DA3 pose translation 会由 scene units 转成米再传给模型，metric depth 再转回 scene units。真实模型证明两帧或共线相机中心不足以保证上游 3D Umeyama 对齐可解，因此 pose conditioning 现在只在至少三帧且中心矩阵秩不小于 2 时启用；否则安全使用 RGB-only 推理。

## 缓存与泄漏验证

- `da3_cache_enabled=false` 不读写缓存；fake-model 和真实 checkpoint 都验证与 cache miss 结果等价。
- cache metadata/key 隔离 source、model id/revision、DA3 source revision、RGB digest、window/preprocess/output/confidence、K、extrinsics、pose-conditioning、scene name、`scene_units_per_meter`、near/far 和 adapter version。
- metadata 不匹配严格 miss；测试覆盖 model revision、process resolution、K、pose 和 scale 变化。
- GT 使用独立 provider 且不访问 DA3 cache。修改输入帧中的 `zbuf` 和 renderer `mask` 不改变 DA3 输出或 key。
- 默认 confidence percentile 改为 `null`：保存原始 confidence，但未校准前不以任意 40th percentile 丢弃有限有效深度。显式阈值仍可配置并进入 key。

## 接线结论

`macarons/testers/magician_planning.py` 与 `macarons/testers/scene.py` 现在共用同一组规划深度 helper。`false + DA3` 在加载规划模型和数据前完成以下检查：

1. `kind_depth_map` 必须严格解析为已注册的 `DA3`；没有 GT fallback。
2. 每个请求场景必须在 `da3_scene_units_per_meter` 中有显式正值标定；`scene_scale_factor=10` 不再被误当物理单位。
3. provider 输出的 `valid_mask & error_mask` 同时用于 point cloud 和 signed distance；同一 provider 相机用于 point cloud、FoV proxy 和 signed-distance 投影。
4. point cloud、proxy view/occupancy/out-of-field 状态和 GT-reference coverage 通过共享 helper 更新，两个入口不再各自复制这段逻辑。

DA3 pose translation 会由 scene units 转成米再传给模型，metric depth 再转回 scene units。真实模型证明两帧或共线相机中心不足以保证上游 3D Umeyama 对齐可解，因此 pose conditioning 现在只在至少三帧且中心矩阵秩不小于 2 时启用；否则安全使用 RGB-only 推理。

## 缓存与泄漏验证

- `da3_cache_enabled=false` 不读写缓存；fake-model 和真实 checkpoint 都验证与 cache miss 结果等价。
- cache metadata/key 隔离 source、model id/revision、DA3 source revision、RGB digest、window/preprocess/output/confidence、K、extrinsics、pose-conditioning、scene name、`scene_units_per_meter`、near/far 和 adapter version。
- metadata 不匹配严格 miss；测试覆盖 model revision、process resolution、K、pose 和 scale 变化。
- GT 使用独立 provider 且不访问 DA3 cache。修改输入帧中的 `zbuf` 和 renderer `mask` 不改变 DA3 输出或 key。
- 默认 confidence percentile 改为 `null`：保存原始 confidence，但未校准前不以任意 40th percentile 丢弃有限有效深度。显式阈值仍可配置并进入 key。

## 真实 mesh 阻断项闭环

### PyTorch3D CUDA 环境

官方安装说明列出的兼容上限是 PyTorch 2.4.1，因此环境从未经官方列出的
`torch 2.7.1+cu118` 调整为 `torch 2.4.1+cu121`、
`torchvision 0.19.1+cu121` 和 `triton 3.0.0`。PyTorch3D 固定为：

```text
facebookresearch/pytorch3d@9381c4016376345bb795b97c45a6c2de66db354a
PyTorch3D 0.7.9
CUDA compiler/runtime 12.1
Python 3.10.4
NVIDIA GeForce RTX 3090
```

目标机以 `CUDA_HOME=/usr/local/cuda-12.1`、`TORCH_CUDA_ARCH_LIST=8.6`
从源码生成 55,573,533-byte wheel。`scripts/validate_pytorch3d_runtime.py`
不是只做 import：它在 `cuda:1` 直接调用编译后的 `pytorch3d._C` mesh
rasterizer，32×32 图像得到 338 个覆盖像素，338 个深度全部有限，四类输出均为
CUDA tensor；五项检查全部通过。RaDe-GS 自带的
`diff-gaussian-rasterization` 也在同一 Torch/CUDA 环境完成源码编译，用于
MAGICIAN beam rendering。

### Eiffel 物理尺度标定

物理基准采用[埃菲尔铁塔官方网站的 330 m 现高](https://www.toureiffel.paris/en/news/history-and-culture/300-330-meters-story-towers-height)。
目标数据文件与测量为：

```text
data/Macarons++/eiffel/eiffel_rgb.obj
sha256=fcbf08c0e224ebf2c844f558dbc1c095dbce00d852078632c839515d40075896
vertices=1,098,614; triangles=1,419,054
```

OBJ 的塔体由断开的金属构件组成，因此不是取整个场景 bbox。测量先按三角面顶点
邻接求连通分量，再保留 `max_y > 1.5` 且 x/z bbox 严格位于 `[-3,3]`
OBJ units 的构件，共 75 个。所得塔脚 `y=0.442077`、塔尖
`y=9.157959`；运行时 `scene_scale_factor=10`，所以：

```text
scene_units_per_meter
  = (9.157959 - 0.442077) * 10 / 330
  = 0.2641176363636364
```

官方网站同时给出的 125 m 地面宽度对 mesh footprint 的交叉检查得到
`0.23766064 scene units/m`，与高度标定差 10.0%。这项差异作为近似 mesh 的
建模不确定性保留，不把本值描述为测绘精度。完整来源、hash、选择规则、原始量和
公式在 `configs/test/scene_metric_calibrations.json`；
`scripts/validate_eiffel_metric_calibration.py` 在目标数据上复算时六项检查全部通过。
